# Capital Cortex API

The machine-readable contract is `docs/openapi.json`, regenerated by `make openapi` (CI fails if it is
stale). It is served live at `/v1/openapi.json` and browsable at `/v1/docs`.

## Conventions (§8)

- **Auth:** every `/v1` endpoint needs an OIDC bearer token from Keycloak realm `cortex` with audience
  `cortex-api`. Admin, Approver, Auditor and Executive tokens must carry MFA (`amr` contains `otp`).
  Approval decisions additionally need MFA performed within the last 5 minutes (step-up).
- **Authorisation:** RBAC from `config/roles.yaml`, then an OPA decision (`data.cortex.authz`). Both must
  allow.
- **Errors:** RFC-7807 `application/problem+json` with `type`, `title`, `status`, `detail`, `instance`,
  `trace_id`. Extra members: `permission`, `reasons` (OPA denials), `mfa_required`, `step_up`, and `phase`
  (for 501).
- **501 "Coming in Phase n":** endpoints of later phases are live in the contract. They authorise as they
  will when built, then return 501 with `phase`.
- JSON, ISO-8601 timestamps, cursor pagination (`cursor`, `next_cursor`), and an `Idempotency-Key` header on
  POSTs (enforced from Phase 1). Every recommendation response includes `confidence` and `evidence[]`
  (Phase 2).

## Live in Phase 0

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/v1/me` | authenticated | roles, effective permissions, MFA state, clearance |
| GET | `/v1/meta` | authenticated | version, current phase, feature→phase map, demo flags |
| GET | `/v1/audit` | `audit:read` | filters `actor`, `action` (supports `*`), `target`; cursor pagination. The read itself is audited |
| GET | `/v1/audit/verify` | `audit:verify` | `{ok, checked, head_seq, head_hash, first_broken_seq, reason}` |
| GET | `/v1/approvals?status=` | `approval:read` | queue ordered by deadline |
| GET | `/v1/admin/budgets` | `budget:read` | today's LLM spend vs caps |
| GET | `/v1/admin/llm-router` | `admin:read` | tiers and providers (secret refs removed) |
| GET | `/v1/ingestion/dlq?stream=` | `ingestion:read` | DLQ contents (actor tokens removed) |
| POST | `/v1/ingestion/dlq/{dlq_id}/replay` | `source:run` | re-publishes to the source stream |
| POST | `/v1/system/ping` · GET `/v1/system/ping/{id}` | `system:ping` | ops round-trip through bus → worker → audit |
| GET | `/healthz`, `/readyz` | none | outside `/v1`; no data |

## Live in Phase 1

| Method | Path | Permission | Notes |
|---|---|---|---|
| GET | `/v1/opportunities` | `opportunity:read` | filters `class`, `stage`, `geo`, `band`, `status`, `source`, `deadline_before/after`, `q` (full text), `min_completeness`, `owner`, `demo`; `sort` = score\|deadline\|amount\|recent\|completeness; facets (with country names and ISO numeric codes); cursor pagination |
| GET | `/v1/opportunities/{id}` | `opportunity:read` | factors with value, weight, method, evidence and gap; classification evidence; signal provenance per field; revision history; activity (the read is audited) |
| PATCH | `/v1/opportunities/{id}` | `opportunity:write` | `pipeline_stage`, `owner_id`, human `class` override (sticky), `status` (archive needs `archive_reason`) |
| POST | `/v1/opportunities/bulk` | `opportunity:write` | `assign` \| `rescore` \| `archive` (reason required) \| `stage` |
| POST | `/v1/opportunities/{id}/rescore` | `opportunity:write` | recompute with the active profile |
| GET/POST | `/v1/scoring/profiles` | `scoring:read` / `scoring:write` | versions are immutable; POST creates the next version |
| POST | `/v1/scoring/profiles/{id}/activate` | `scoring:activate` (admin) | queues a batch rescore |
| POST | `/v1/scoring/preview` | `scoring:preview` | re-rank with candidate weights and thresholds; nothing is persisted |
| GET | `/v1/scoring/backtest` | `scoring:read` | hit rate by band over realised outcomes |
| GET/PUT | `/v1/organization/self` | `opportunity:read` / `scoring:preview` | the self-organisation profile that scoring compares against; PUT rescores everything |
| GET | `/v1/graph/query` | `graph:read` (`graph:cypher` + admin for `template=cypher`) | templates `neighbourhood` (depth 1–2), `provenance`, `label`; raw Cypher is read-only |
| GET | `/v1/graph/paths?from=&to=` | `graph:read` | up to 5 paths, ≤ `max_hops` |
| GET | `/v1/graph/stats` | `graph:read` | vertex and edge counts per label |
| GET/POST | `/v1/entities/merge-queue` | `entity:read` / `entity:merge` | candidates 0.80–0.92; manual proposals |
| POST | `/v1/entities/{id}/merge` · `/unmerge` | `entity:merge` | `{"reject": true}` rejects; merges are reversible and audited |
| GET | `/v1/sources` · `/v1/sources/{id}/runs` | `ingestion:read` | registry, health, last run, totals, run history |
| PATCH | `/v1/sources/{id}` | `source:run` | `{"enabled": bool}` |
| POST | `/v1/sources/{id}/run` | `source:run` | queued to the worker (pull sources) |
| POST | `/v1/sources/{id}/upload` | `source:run` | multipart CSV/XLSX, processed immediately |
| POST | `/v1/sources/{id}/entries` | `source:run` | manual entries (1–100) |
| POST | `/v1/signals` | `signal:write` (service) | raw items for a configured source |
| GET | `/v1/dashboards/{name}` | `dashboard:read` | `executive` \| `pipeline` \| `runway` \| `grants` \| `geo` (`cost` → Phase 3) |
| GET/POST | `/v1/forecasts` | `forecast:read` / `forecast:write` | persisted base, downside and upside forecasts |
| POST | `/v1/forecasts/scenarios/run` | `forecast:read` | presets + custom scenarios (burn delta, inflow probability multiplier/delay, hires, raise); not persisted |
| GET | `/v1/forecasts/snapshots` | `forecast:read` | imported monthly financials |
| POST | `/v1/forecasts/snapshots/preview` · `/import` | `forecast:write` | CSV/XLSX → suggested column mapping → import with provenance (file SHA-256 + row) |
| GET | `/v1/events/stream` | `opportunity:read` | SSE notifications: `opportunity.created`, `opportunity.updated`, `opportunity.bulk`, `scoring.rescored`, `source.run` |

All POSTs accept `Idempotency-Key`: a replay returns the stored response with `Idempotent-Replay: true`, and
reusing a key with a different body returns 422.

## Planned surface

Everything else in §8 (relationships, agents
with SSE, approval decisions, outbox, alerts, outcomes, proposals, data room, Copilot
and admin writes) is registered with its permission and phase in
`cortex/l8_actuation/api/routers/phased.py` and marked `x-cortex-phase` in the OpenAPI spec.

## Getting a token (dev)

```bash
# service account (client credentials)
curl -s -X POST http://localhost:8380/realms/cortex/protocol/openid-connect/token \
  -u cortex-worker:dev-worker-secret-change-me -d grant_type=client_credentials | jq -r .access_token
```

Human users sign in through the UI (authorization code + PKCE). `scripts/smoke.py` shows the full browser
flow, including TOTP, done programmatically.
